# Bundle Update Log

## 2026-08-18

- **Review-response primitive (`pr-fix`)**: added the third member of the PR skill family — `pr-gate` reviews, **`pr-fix` responds**, `pr-enqueue` merges. `.claude/skills/pr-fix/SKILL.md` carries the loop (harvest every review body + unresolved GraphQL review thread into an append-only ledger → triage each finding against the PR head with the closed vocabulary `fix` / `rejected-with-evidence` / `deferred-to-issue` / `ask-operator` → fix the survivors one commit per finding in `.claude/worktrees/pr-<N>` → stop before the push). The security-relevant half is deterministic, not prose: `task pr:fix:facts` is the single read-only `gh` surface (the unresolved-thread flag needs GraphQL — the REST review-comments endpoint carries no `isResolved`, so a REST-only gather cannot tell a settled thread from an open one), and the pure `task pr:fix:admit` classifier decides admissibility (`fork` / `not-author` / `dirty` / `no-findings` / `incomplete` all stop the run) with `approvals-at-risk:N` / `review-behind-head` / `draft` as non-blocking warnings, bound red-green by `task test:pr-fix-admit` in `task ci`. Isolation is `task worktree:pr` (checkout at `origin/<head>`, refusing a locally-diverged branch, idempotent, `worktree:pr:remove` refusing while changes are uncommitted). Two design constraints worth recording: the governance-path partition is **not** duplicated into the new classifier (it has one source, `pr:triage`'s `governance` class — governance paths block unattended *approval*, not an author's own fix), and no unattended loop dispatches the skill, since it writes commits and the push dismisses standing approvals under `dismiss_stale_reviews`. `AGENTS.md` and `CLAUDE.md` (both in several concepts' `sources:`) gained the registration paragraph and the four command-table rows — purely additive, falsifying no present-tense claim in any concept; the timestamps of the concepts carrying them are bumped accordingly.

## 2026-08-16

- **`storage-objects/garage-operator` runs namespace-scoped (#795)**: the component published the chart's cluster-wide default — a manager `ClusterRole`/`ClusterRoleBinding` granting `get`/`list`/`watch` on every Secret in the cluster (a List response carries the Secret contents, so this is disclosure, not just write) plus `create` on Pods and workload kinds in every namespace, which by [Kubernetes' own RBAC guidance](https://kubernetes.io/docs/concepts/security/rbac-good-practices) composes to cluster-admin, since creating a workload confers the API access of any ServiceAccount in the target namespace. Setting `watchNamespaces` in `helm/garage-operator.yaml` flips the chart to its namespace-scoped mode: the artifact now renders **0 manager `ClusterRole`s and 0 manager `ClusterRoleBinding`s**, a `Role`/`RoleBinding` in the watched namespaces instead, and `--watch-namespaces=garage-operator`. The chart gates its metrics-authn RBAC on the same condition — an upstream defect, since delegated authn is unrelated to watch scope — so those three objects are re-shipped verbatim as `manifests/10-metrics-rbac.yaml`; `create` on `tokenreviews` + `subjectaccessreviews` is now the artifact's entire cluster-scoped surface. Costs, all documented in the component README: `spec.storage.nodeLocalPools` and `spec.zoneFrom.nodeLabel` need cluster-scoped Node access and are unavailable in the published shape; an operand namespace must be granted before the operator does anything (`Role` + `RoleBinding` + a `test`-guarded JSON6902 patch on `--watch-namespaces`, § Watching additional namespaces); a CR in an unwatched namespace is admitted and silently never reconciled (new § Failure modes entry — the webhooks carry no `namespaceSelector`). Re-verified and bumped `reference/sub-layers/storage-objects.md`, whose cluster-wide-grant note the change falsified. Deliberately **not** done: documenting and gating the cluster-wide grant per component (the shape of the abandoned PR #796) — a sweep of all 68 rendered artifacts found 13 components with a bound cluster-wide secret-write `ClusterRole`, so the recurrence guard belongs in `policies/` (ADR-0018), not in a per-component apparatus.

- **Optional customization keys (#794)**: added `decisions/DR-0004-optional-customization-keys.md` recording the additive top-level `optional` block in `schemas/customization.schema.json` — env keys the artifact carries a working baked default for, which a consumer sets only to change behaviour, keeping `required` strictly the must-supply channel. Entries are objects (`name`, `description`, `default` required; descriptive `group` optional); `restart_required` was considered and deliberately not built (every key in the class resolves at pod start, so the field would have exactly one valid value) and is a schema-reject fixture rather than an unbuilt idea. Re-verified `reference/component-contract.md` (lists `schemas/customization.schema.json` + `AGENTS.md` in `sources:`): the `required`-only description was incomplete, corrected and timestamp bumped. Added the DR-0004 bullet to `decisions/index.md`. Named residual: nothing compares a declared key against the render, so a declared key with no matching `${KEY}` placeholder passes green.
